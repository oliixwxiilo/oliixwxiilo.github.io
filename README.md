- 软件源地址：https://oliixwxiilo.github.io/

## 插件资料目录

- 插件图标：`assets/icons/`
- 插件截图：`assets/screenshots/插件名称/`
- 插件中文资料、介绍和更新日志：`metadata/packages/`
- 当前版本安装包：`pool/main/`
- 历史版本安装包：`pool/old/插件名称/`

## 上传文件与自动构建

日常维护时，只需要把文件上传到上面对应的目录，并将更改提交到 `main` 分支。提交后，GitHub Actions 会自动启动构建和网站部署。

### 各目录应该放什么

| 文件类型 | 上传目录 | 说明 |
| --- | --- | --- |
| 插件安装包（`.deb`） | `pool/main/` | 放当前发布版本的安装包 |
| 插件图标（`.png`、`.jpg`、`.jpeg`、`.webp`） | `assets/icons/` | 优先按软件包标识、标识末段或插件名称自动匹配；也可在 JSON 中指定路径 |
| 插件截图（`.png`、`.jpg`、`.jpeg`、`.webp`） | `assets/screenshots/插件名称/` | 自动按插件名称、软件包标识或标识末段匹配目录内全部图片；也可在 JSON 中指定 |
| 插件资料（`.json`） | `metadata/packages/` | 可选；用于补充介绍、截图、更新日志、支持系统和历史版本等资料 |
| 历史版本安装包（`.deb`） | `pool/old/插件名称/` | 需要保留旧版本供用户查看或下载时放在这里 |

### 自动构建会处理什么

提交到 `main` 后，自动构建流程会：

1. 扫描当前版本和历史版本的 `.deb` 安装包。
2. 读取安装包中的真实包标识、版本号、架构和依赖信息。
3. 自动按软件包标识或插件名称匹配图标，并自动收集 `assets/screenshots/` 下对应插件目录的截图；有 JSON 时读取补充资料，没有 JSON 也能生成基础详情。
4. 自动生成 Sileo 原生插件详情资料和网页详情页。
5. 生成 APT 软件包索引：`Packages`、`Packages.gz`、`Packages.xz`。
6. 重新计算并生成 `Release` 文件中的校验哈希。
7. 将构建结果部署到 GitHub Pages。

### 日常维护注意事项

- **必须提交到 `main` 分支**，才会触发当前自动构建流程。
- 新插件只需上传 `.deb`；图标放入 `assets/icons/`，文件名尽量使用软件包标识、软件包标识末段或插件显示名称。无需为了显示图标专门创建 JSON。
- 更新插件时，将新安装包放入 `pool/main/`，并同步更新 JSON 中的版本号、介绍或更新日志。
- 需要保留旧版本时，将旧安装包放入 `pool/old/插件名称/`。
- 截图放在 `assets/screenshots/插件名称/` 即可自动关联；目录名也可使用软件包标识或标识末段。支持 PNG、JPG、JPEG、WEBP。JSON 中有效的截图路径会优先显示，自动发现的图片会接着补充，重复图片不会重复显示。
- 没有 JSON 时，构建会从 `.deb` 自动读取包标识、版本、架构、依赖等信息，并生成基础详情；介绍、更新日志、支持系统和历史版本等文字资料仍需在 JSON 中补充，不会凭空编造；截图图片只要放入对应目录就能自动发现。
- 不要手动修改自动生成的 `Packages`、压缩索引和 `Release` 文件；它们会在构建时重新生成。
- 提交后可在 GitHub 仓库的 **Actions** 页面查看构建和部署结果。只有部署步骤成功后，网站和软件源内容才算完成更新。
