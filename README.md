## 插件资料目录

- 插件图标：`assets/icons/`
- 插件截图：`assets/screenshots/插件名称/`
- 插件中文资料、介绍和更新日志：`metadata/packages/`
- 当前版本安装包：`pool/main/`
- 历史版本安装包：`pool/old/插件名称/`

## 上传文件与自动构建

日常维护时，只需要把文件上传到上面对应的目录，并将更改提交到 `main` 分支。提交后，GitHub Actions 会自动启动构建和网站部署。

### 各目录应该放什么

| 文件类型 | 上传目录 | 说明 |
| --- | --- | --- |
| 插件安装包（`.deb`） | `pool/main/` | 放当前发布版本的安装包 |
| 插件图标（`.png` 等） | `assets/icons/` | 图标文件名和资料 JSON 中的「插件图标」路径保持一致 |
| 插件截图 | `assets/screenshots/插件名称/` | 截图文件名和资料 JSON 中的「插件截图」路径保持一致 |
| 插件资料（`.json`） | `metadata/packages/` | 填写插件名称、包标识、介绍、版本、更新日志、支持系统等中文资料 |
| 历史版本安装包（`.deb`） | `pool/old/插件名称/` | 需要保留旧版本供用户查看或下载时放在这里 |

### 自动构建会处理什么

提交到 `main` 后，自动构建流程会：

1. 扫描当前版本和历史版本的 `.deb` 安装包。
2. 读取安装包中的真实包标识、版本号、架构和依赖信息。
3. 读取对应的中文 JSON 资料，并关联图标和截图。
4. 自动生成 Sileo 原生插件详情资料和网页详情页。
5. 生成 APT 软件包索引：`Packages`、`Packages.gz`、`Packages.xz`。
6. 重新计算并生成 `Release` 文件中的校验哈希。
7. 将构建结果部署到 GitHub Pages。

### 日常维护注意事项

- **必须提交到 `main` 分支**，才会触发当前自动构建流程。
- 新插件需要同时准备安装包和对应的中文资料 JSON；图标、截图按需添加。
- 更新插件时，将新安装包放入 `pool/main/`，并同步更新 JSON 中的版本号、介绍或更新日志。
- 需要保留旧版本时，将旧安装包放入 `pool/old/插件名称/`。
- JSON 中填写的图标、截图路径必须与仓库中的实际文件路径和文件名一致。
- 自动构建负责读取资料、生成索引和详情页，不会自动编写插件介绍或更新日志；这些内容需要在 JSON 中维护。
- 不要手动修改自动生成的 `Packages`、压缩索引和 `Release` 文件；它们会在构建时重新生成。
- 提交后可在 GitHub 仓库的 **Actions** 页面查看构建和部署结果。只有部署步骤成功后，网站和软件源内容才算完成更新。
